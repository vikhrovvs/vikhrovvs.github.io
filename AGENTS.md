# Инструкции для Codex

## Контекст проекта

- Это статическая личная страница `vikhrovvs.github.io` с независимыми мини-проектами.
- Перед работой прочитай `README.md` и `MEMORY.md`, затем проверь `git status` и последние коммиты.
- `MEMORY.md` содержит устойчивые продуктовые и архитектурные решения. Поддерживай его актуальным, когда меняются маршруты, форматы данных, правила игры или процесс публикации; не превращай его в журнал каждого коммита.

## Архитектурные границы

- Публикуемый корень — `site/`. GitHub Actions загружает эту папку как готовый артефакт без сборки.
- Каждый проект живёт в собственной папке внутри `site/`; главная страница только связывает проекты.
- Сохраняй приложение статическим и пригодным для GitHub Pages. Не добавляй backend, базу данных, фреймворк, bundler или production-зависимости без явного согласования.
- Словограф и игра используют общий файл `site/anagrams/data/graph.json`. Не дублируй граф и не редактируй его вручную; исходный CSV пересобирается через `scripts/build-data.mjs`.
- Сохраняй существующий визуальный язык: тёмный фон, светлый текст, лаймовый акцент, `Manrope` и `Onest`. Новые экраны должны быть адаптивными и доступными с клавиатуры.

## Формат графа

- `nodes[i]`: `{ id, label, frequency, words }`, где `words` — пары `[слово, ipm]` одной анаграммной группы.
- `edges`: тройки `[a, b, type]`, где `type` равен `add` или `replace`, а `a` и `b` — индексы в `nodes`.
- В игровой механике шаг делается между вершинами, а не между отдельными вариантами анаграмм внутри вершины.
- Нормализация пользовательского ввода: trim, нижний регистр с русской локалью, NFC.

## Порядок работы

1. Найди минимальный набор затрагиваемых файлов и сохрани чужие незавершённые изменения.
2. Для изменения поведения обнови код, связанную документацию и `MEMORY.md`, если изменилось устойчивое решение.
3. Запусти `python3 scripts/check_site.py`. Для изменённых JavaScript-файлов дополнительно выполни `node --check <file>`, если Node доступен.
4. Для пользовательских или браузерных ошибок проверь опубликованную либо локальную страницу после исправления, включая консоль и фактическое вычисленное состояние интерфейса.
5. Если изменился CSS или JavaScript, уже подключённый на опубликованной странице, увеличь параметр версии в соответствующем `href`/`src`, чтобы GitHub Pages и браузер не удерживали старый файл.
6. Делай небольшие логические коммиты. Пользователь попросил готовые коммиты сразу отправлять в `main`; после push проверь успешное завершение workflow и публичную страницу.

## Безопасность и качество

- Не коммить секреты, токены, приватные ключи, `.env`, локальные настройки IDE и логи Codex.
- Не удаляй и не пересоздавай `graph.json` без необходимости: это крупный отслеживаемый артефакт.
- Не показывай кратчайший путь в игре до финиша и не добавляй подсказки, таймер, жизни, очки или хранение статистики без отдельного продуктового решения.
- При изменении daily-алгоритма сохраняй детерминированность: одна UTC-дата должна давать одну пару для всех пользователей.
