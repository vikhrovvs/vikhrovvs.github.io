# Алгоритм «Словесного квадрата»

## Модель задачи

Для каждой позиции каждого существенного слова создаётся переменная `X[word, position]`. Значение переменной — номер клетки от `0` до `15`.

Это позволяет не перебирать `16!` готовых досок. Вместо этого решатель постепенно назначает только те клетки, которые реально используются словами.

Ограничения ровно повторяют правила:

1. `X[w, i]` и `X[w, i + 1]` должны быть соседями в решётке короля 4 × 4.
2. Все `X[w, …]` одного слова различны.
3. Переменные с разными буквами не могут получить одну клетку. Одинаковые буквы из разных слов — могут.

Когда все переменные назначены, буква клетки однозначно определяется назначенными в неё позициями. Неиспользованные клетки остаются пустыми: они поддерживаются для наборов менее чем из 16 уникальных букв, но не создают искусственных вариантов заполнения.

## Предварительные проверки

Кроме очевидных `len(word) <= 16` и `len(unique_letters) <= 16`, есть более сильное необходимое условие.

Для каждой буквы берётся максимальное число её повторов в одном слове. Например, словам `топот` и `потоп` нужны как минимум две клетки `т`, две `о` и одна `п` — не сумма повторов в обоих словах, потому что между словами клетки можно переиспользовать. Сумма таких максимумов не должна превышать 16.

Короткое слово удаляется из CSP, если оно является непрерывной подстрокой более длинного слова или его разворота. Путь длинного слова автоматически содержит путь короткого; после решения путь короткого восстанавливается обычным DFS по доске.

## Распространение ограничений

Домен каждой переменной — 16-битная маска. После назначения клетки решатель:

- удаляет её из остальных позиций того же слова;
- удаляет её из переменных с другой буквой;
- сужает домены соседних позиций до геометрических соседей оставшихся клеток;
- проверяет, что для каждого слова всё ещё существует хотя бы один полный простой путь;
- проверяет двудольным matching, что всем буквам можно выделить необходимое число разных клеток.

Если домен становится пустым или одна из проверок не проходит, ветвь немедленно отбрасывается.

## Ветвление и полнота

Следующей выбирается переменная с минимальным оставшимся доменом (MRV). Значения пробуются в порядке, который сначала сохраняет больше вариантов для соседних позиций.

У пустого квадрата есть восемь поворотов и отражений. Для первого назначения достаточно проверить три типа клеток: угол, край и внутреннюю клетку. Это не теряет решений, потому что любое решение можно симметрично перенести так, чтобы первая выбранная позиция попала в представителя своего типа.

Если все ветви закончились конфликтом, решения действительно нет. Ограничение в 20 секунд относится только к браузерному запуску: ответ `timeout` не является доказательством отсутствия решения.

## Перечисление уникальных решений

Обычный `solve()` завершает обход на первом листе. `enumerate_solutions()` вместо этого вызывает callback для найденного поля и продолжает DFS. Благодаря callback первое решение сразу попадает из Python Worker в интерфейс, пока остальные ветви ещё исследуются.

Поле канонизируется по восьми симметриям квадрата: четырём поворотам и четырём отражениям. В множество найденных решений записывается лексикографически минимальный представитель, поэтому симметричные поля и разные наборы маршрутов по одному полю считаются один раз.

Основной быстрый случай — ровно 16 уникальных букв. Тогда каждая буква обязана занять ровно одну клетку, поэтому одной буквенной раскладке соответствует одно назначение переменных независимо от выбранного пути восстановления.

Первые 200 канонических полей передаются в галерею. Счётчик продолжает расти до полного обхода, 20-секундного таймаута или защитного предела 100 тысяч решений. Только полный обход даёт точное число; в остальных случаях UI показывает нижнюю границу.

## Где менять поведение

- Нормализация и первичные проверки: `_normalise_words()` и `solve()`.
- Список соседей поля: `_build_neighbour_masks()`.
- Распространение ограничений: `WordGridCsp._propagate()`.
- Выбор следующей переменной и порядок клеток: `_choose_variable()` и `_ordered_cells()`.
- Лимиты браузерного поиска и галереи: `TIME_LIMIT_SECONDS`, `DISPLAY_LIMIT` и `MAX_SOLUTIONS` в `app.js`; Python содержит соответствующие безопасные значения по умолчанию.

`solve(raw_words, time_limit_seconds)` возвращает одно решение. `enumerate_solutions(...)` считает уникальные поля и принимает callback для потоковых обновлений. `solve_json()` и `enumerate_json()` — тонкие границы для Web Worker; сам поиск от JavaScript не зависит.
