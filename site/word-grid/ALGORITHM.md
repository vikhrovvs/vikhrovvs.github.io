# Алгоритм «Словесного квадрата»

## Постановка задачи

Дан набор слов. Требуется расставить буквы по клеткам квадрата 4 × 4 так, чтобы каждое заданное слово можно было прочитать как путь по полю:

1. соседние буквы слова находятся в клетках с общей стороной или общей вершиной;
2. внутри одного слова ни одна клетка не используется повторно;
3. разные слова могут проходить через одни и те же клетки.

В каждой занятой клетке находится ровно одна буква. Если для решения нужны не все 16 клеток, остальные разрешается оставить пустыми.

Нужно определить, существует ли хотя бы одно такое заполнение, и при положительном ответе предъявить его. Текущая реализация решает более общую задачу: перечисляет уникальные заполнения с точностью до поворотов и отражений квадрата, сразу показывает первое найденное и после полного обхода сообщает их точное количество. Если весь набор разместить нельзя, решатель ищет подмножество с максимальным числом слов и строит поля уже для него.

## Модель задачи

Для каждой позиции каждого существенного слова создаётся переменная `X[word, position]`. Значение переменной — номер клетки от `0` до `15`.

Это позволяет не перебирать `16!` готовых досок. Вместо этого решатель постепенно назначает только те клетки, которые реально используются словами.

Ограничения ровно повторяют правила:

1. `X[w, i]` и `X[w, i + 1]` должны быть соседями в решётке короля 4 × 4.
2. Все `X[w, …]` одного слова различны.
3. Переменные с разными буквами не могут получить одну клетку. Одинаковые буквы из разных слов — могут.

Когда все переменные назначены, буква клетки однозначно определяется назначенными в неё позициями. Неиспользованные клетки остаются пустыми: они поддерживаются, когда найденным маршрутам нужно менее 16 клеток, но не создают искусственных вариантов заполнения.

## Предварительные проверки

Кроме очевидных `len(word) <= 16` и `len(unique_letters) <= 16`, есть более сильное необходимое условие.

Для каждой буквы берётся максимальное число её повторов в одном слове. Например, словам `топот` и `потоп` нужны как минимум две клетки `т`, две `о` и одна `п` — не сумма повторов в обоих словах, потому что между словами клетки можно переиспользовать. Сумма таких максимумов не должна превышать 16.

Короткое слово удаляется из CSP, если оно является непрерывной подстрокой более длинного слова или его разворота. Путь длинного слова автоматически содержит путь короткого; после решения путь короткого восстанавливается обычным DFS по доске.

## Распространение ограничений

Домен каждой переменной — 16-битная маска. После назначения клетки решатель:

- удаляет её из остальных позиций того же слова;
- удаляет её из переменных с другой буквой;
- сужает домены соседних позиций до геометрических соседей оставшихся клеток;
- проверяет, что для каждого слова всё ещё существует хотя бы один полный простой путь;
- проверяет двудольным matching, что всем буквам можно выделить необходимое число разных клеток.

Если домен становится пустым или одна из проверок не проходит, ветвь немедленно отбрасывается.

## Ветвление и полнота

Следующей выбирается переменная с минимальным оставшимся доменом (MRV). Значения пробуются в порядке, который сначала сохраняет больше вариантов для соседних позиций.

У пустого квадрата есть восемь поворотов и отражений. Для первого назначения достаточно проверить три типа клеток: угол, край и внутреннюю клетку. Это не теряет решений, потому что любое решение можно симметрично перенести так, чтобы первая выбранная позиция попала в представителя своего типа.

Если все ветви закончились конфликтом, решения действительно нет. В браузере пользователь выбирает лимит от 20 секунд до 10 минут: ответ `timeout` не является доказательством отсутствия решения.

## Оптимизация почти заполненного поля

Главное ускорение для длинных наборов даёт учёт числа клеток каждой буквы до начала обычного DFS.

Если некоторой букве разрешена ровно одна клетка, все её позиции в разных словах фактически являются одной переменной. Решатель синхронизирует их домены после каждого сужения. Например, выбор клетки для `р` сразу распространяет ограничения от всех вхождений `р`, а не ждёт, пока каждое из них будет назначено отдельно.

Особенно важен случай, когда необходимые повторы занимают 15 из 16 клеток. Любое решение относится ровно к одному из сценариев:

1. шестнадцатая клетка остаётся пустой, а каждая буква занимает минимально необходимое число клеток;
2. поле заполнено целиком, и ровно одна буква получает одну дополнительную клетку.

Алгоритм перебирает эти непересекающиеся сценарии отдельно. Внутри каждого почти все верхние границы становятся точными, поэтому синхронизация одинаковых букв и отсечения срабатывают намного раньше. Разбиение полное: оно меняет порядок поиска, но не исключает допустимые поля.

Дополнительно после ветвления проверяются только слова, чьи домены действительно изменились. Остальные слова уже имели допустимый путь в родительском состоянии, поэтому повторять для них ту же проверку не требуется.

## Перечисление уникальных решений

Обычный Python API `solve()` завершает обход на первом листе. Браузер всегда вызывает `enumerate_solutions()`: функция передаёт найденное поле в callback и продолжает DFS. Благодаря callback первое решение сразу попадает из Python Worker в интерфейс, пока остальные ветви ещё исследуются. Остановить Worker можно отдельной кнопкой.

Поле канонизируется по восьми симметриям квадрата: четырём поворотам и четырём отражениям. В множество найденных решений записывается лексикографически минимальный представитель, поэтому симметричные поля и разные наборы маршрутов по одному полю считаются один раз.

Основной быстрый случай — ровно 16 уникальных букв. Тогда каждая буква обязана занять ровно одну клетку, поэтому одной буквенной раскладке соответствует одно назначение переменных независимо от выбранного пути восстановления.

## Максимальное подмножество слов

Поиск подмножества запускается только после того, как полный набор **доказанно** неразрешим. Если поиск полного набора закончился по тайм-ауту, отбрасывать слова нельзя: решение для всех слов всё ещё может существовать.

Кандидаты рассматриваются по убыванию числа слов: сначала все допустимые подмножества размера `n - 1`, затем `n - 2` и так далее. Поэтому первое подмножество, для которого CSP нашёл поле, имеет максимальную мощность `k`. Алгоритм останавливается на одном таком подмножестве; другие подмножества того же максимального размера не перечисляются.

Это всё ещё экспоненциальная задача в худшем случае, но до дорогой геометрической проверки применяются несколько отсечений:

- слово длиннее 16 букв сразу не может войти в кандидат;
- при добавлении слова инкрементально пересчитывается необходимое число клеток каждой буквы — максимум её повторов в одном из выбранных слов;
- ветвь отбрасывается, как только сумма этих максимумов превышает 16;
- если разные наборы слов после удаления вложенных слов дают один набор существенных ограничений, заведомо неразрешимый CSP повторно не запускается;
- сначала пробуются слова с наиболее часто разделяемыми буквами: это не влияет на полноту, но обычно раньше приводит к совместимому кандидату.

Проверка `ровно 16 уникальных букв` является частным случаем клеточного бюджета. Реализация допускает и меньшее число разных букв, в том числе с повторами внутри слова. Клетки, которые не понадобились найденным маршрутам, остаются пустыми.

На подбор подмножества и последующее перечисление его полей действует общий пользовательский лимит времени. Максимальность заявляется только после полного исключения всех более крупных кандидатов. Если времени не хватило, интерфейс не выдаёт меньшее подмножество за оптимальное и предлагает увеличить лимит.

Первые 200 канонических полей передаются в галерею по порядку нахождения. Параллельно решатель хранит топ-100 самых запутанных полей в ограниченной min-heap. После окончания поиска эта сотня сортируется по убыванию запутанности и передаётся в отдельную листаемую подборку. Счётчик продолжает расти до полного обхода, выбранного таймаута или защитного предела 100 тысяч решений. Только полный обход даёт точное число и глобальный топ; в остальных случаях UI показывает нижнюю границу и топ среди уже найденных.

## Запутанность

Для пути из `L` букв берутся:

- `T` — число смен точного направления шага (учитываются все восемь направлений);
- `F` — число использованных типов движения: горизонталь, вертикаль, диагональ;
- `D` — число диагональных шагов.

При `L > 1` запутанность равна

```text
C = (T + max(0, F - 1) + D / 2) / (L - 1)
```

Для однобуквенного слова `C = 0`. Нормализация на число шагов не даёт длинным словам автоматического преимущества. Половина балла за диагональ отличает короткое диагональное слово от очевидного горизонтального или вертикального, но весит меньше настоящего поворота.

Если слово читается на одном поле несколькими путями, алгоритм Дейкстры по состояниям `(позиция, клетка, использованные клетки, предыдущее направление, типы движения)` выбирает путь с **минимальной** запутанностью: игрок заметит самое простое вхождение, поэтому оценивать более сложный альтернативный маршрут было бы нечестно.

Поле ранжируется лексикографически по паре:

```text
(минимальная запутанность слова, средняя запутанность слов)
```

Оба значения максимизируются. Во время обхода нет необходимости сортировать все поля: для каждого кандидата обновляется куча фиксированного размера 100 за `O(log 100)`, а в конце сортируются только её элементы. При равной паре оценок выше остаётся раньше найденное поле. Если обход упёрся в таймаут или защитный лимит, интерфейс честно называет подборку «топом среди найденных», а не гарантированным глобальным топом.

Для сравнения с произвольной конфигурацией перечисление также собирает распределение **средней** запутанности поля. Максимум обновляется за `O(1)`, 100 наименьших значений хранятся в ограниченной max-heap, а для точной медианы ведётся счётчик частот округлённых оценок. В конце сортируются только различные значения оценки, а не все найденные поля. «Среднее нижних 100» — среднее арифметическое средней запутанности у 100 наименее запутанных полей (или у всех полей, если решений меньше 100).

`evaluate_board()` принимает полное поле из 16 букв, проверяет, что каждое исходное слово действительно читается, и для каждого слова находит самое простое вхождение тем же алгоритмом, что используется при ранжировании. Поэтому пользовательская и сгенерированные конфигурации сравниваются в одной шкале.

## Где менять поведение

- Нормализация, геометрия поля и первичные редукции: `grid_model.py`.
- Автоматический переход к максимальному подмножеству: `maximise_words_and_enumerate()` в `solver.py`; генерация кандидатов — `_iter_candidate_subsets()` в `subset_selection.py`.
- Распространение ограничений и ветвление: класс `WordGridCsp` в `csp.py`.
- Разбиение случая с одной свободной клеткой: `_cell_count_plans()`.
- Выбор следующей переменной и порядок клеток: `_choose_variable()` и `_ordered_cells()` в `csp.py`.
- Формула и выбор самого простого маршрута: `_path_complexity()` и `_find_easiest_word_path()` в `complexity.py`.
- Оценка введённого поля и сравнительные ориентиры: `evaluate_board()`, `_average_benchmarks()` и `_median_from_counts()`.
- Лимиты браузерного поиска, галереи и рейтинга: `DEFAULT_TIME_LIMIT_SECONDS`, `MAX_TIME_LIMIT_SECONDS`, `DISPLAY_LIMIT`, `TOP_LIMIT` и `MAX_SOLUTIONS` в `app.js`; Python содержит соответствующие безопасные границы.

`solve(raw_words, time_limit_seconds)` возвращает одно решение. `enumerate_solutions(...)` считает уникальные поля и принимает callback для потоковых обновлений. `evaluate_board(raw_board, raw_words)` оценивает готовую конфигурацию. `solve_json()`, `enumerate_json()` и `evaluate_json()` — тонкие границы для Web Worker; сам поиск от JavaScript не зависит.
