# Обновление графа лесенок

Проверено 2026-11-14 по коду и авторизованным страницам Interoves. В архив добавлена
лесенка №129 от 2026-11-13; №130 от 2026-11-14 намеренно исключена правилом D−1.
Граница дня — Europe/Moscow. Это правило календарной даты, а не выдержка ровно 24 часов.

## Что и когда пересчитывается

| Данные | Место расчёта | Обновление |
|---|---|---|
| Слова, уникальные неориентированные связи, все подсказки, участие в лесенках | `build-ladder-graph.mjs` | Каждая сборка |
| Компоненты, степени вершин, исходная раскладка | Там же | Каждая сборка |
| Длинные простые пути по компонентам | `ladder-paths.mjs` | Каждая сборка; ограниченный поиск, максимум не всегда доказан |
| Общие счётчики, распределения степеней и кратностей, сводка компоненты и её лидер | `app.js` | При загрузке нового графа |
| Вся история, рождения/присоединения/слияния, первые события, серии и все равные рекорды | `history.js` | При загрузке нового графа |
| Старые слова, пересечения с прежними заданиями, повторные связи, возвращения слов | Там же | При загрузке нового графа |
| Скачок крупнейшей, устойчивое большинство, достижение 100/500/1000 слов | Там же | При загрузке нового графа; числа 100/500/1000 — выбранные пороги, не готовые результаты |
| Схемы маленьких компонент | `layout.js` | В браузере из нового графа |
| Оптимизированные координаты большой компоненты и число пересечений | `optimize-gentle-layout.py`, `test-gentle-layout.mjs` | Раньше вручную один раз; теперь при обновлении и в deployment при изменении SHA-256 топологии |

На вкладке истории не найдены вручную записанные статистические результаты.
История использует номера доступных лесенок; длина серии и отсутствие слова считаются
в заданиях, а не в календарных днях. Рекорды относятся ко всему загруженному архиву,
даже при выборе раннего шага. Предзаданные категории событий и пороги — правила UI.
Независимый BFS проверяет каждое историческое состояние.

## Текущий рабочий процесс

1. Открыть Interoves в авторизованном браузере. На 2026-11-14 аккаунт имел доступ
   к полным ответам №129. Для нерешённых заданий доступность ответов не проверена;
   отсутствие слова должно останавливать экспорт, без отправки ответов или изменения игры.
2. Задать `window.ladderExportOptions = { afterNumber: 129 }` и выполнить
   `scripts/export-ladder.browser.js`. Он читает месяцы и только новые задания до D−1.
   Для полного повторного аудита убрать эту опцию. В выгрузку не входят cookies,
   пароль, результаты/время игрока и HTML. Неполная выгрузка не скачивается.
3. Запустить `scripts/update-ladder.py <export.json>` Python-интерпретатором с
   NumPy из `scripts/requirements-ladder.txt`. Импорт проверяет соответствие базового
   номера, полноту, пропуски, даты, индексы и цепочку; перед заменой сохраняет локальный backup.
   Полный экспорт не может потерять уже известную лесенку. Импорт повторной добавочной
   выгрузки с устаревшим базовым номером отклоняется.
4. После проверок использовать `--upload`: Secrets обновляются через существующую
   авторизацию `gh`, manifest получает новый checksum. Затем review, commit manifest,
   координат и кода, push в main, проверка workflow и публичной страницы.

Дата на странице — `lastGameDate`, не `collectedAt`. Граф и координаты загружаются
с HTTP revalidation. Изменяемый JS по-прежнему требует увеличения версии подключения.
При несовпадении координат браузер сохраняет работоспособность через исходную раскладку,
но CI отклоняет такой несогласованный набор: это нельзя считать завершённым обновлением.

## Предложение для ежедневного процесса

Рекомендуемый вариант — локальный collector с отдельным Playwright browser profile
для Interoves. Влад один раз вручную входит в свой аккаунт в этом профиле. Ежедневный
запуск, например в 09:15 МСК, читает только новые задания до вчера, сохраняет экспорт,
вызывает проверенный update pipeline, загружает Secrets и отправляет изменённые manifest
и координаты в main. После пропуска нескольких запусков забирает весь недостающий диапазон.
Один процесс за раз; перед записью синхронизировать main и остановиться при чужих изменениях
или конфликте. При отсутствии нового задания commit и deployment не нужны.

Состояние авторизации остаётся локально вне Git и публичного `site/`. При истечении
сессии процесс завершает работу с понятной ошибкой, сохраняя последнюю публикацию;
повторный вход выполняет Влад вручную. Полные ответы должны быть доступны аккаунту —
сам факт login этого не гарантирует. Не логировать HTML, cookies и storage state.
Playwright официально поддерживает повторное использование авторизованного состояния,
но предупреждает, что оно позволяет выдать себя за пользователя:
[Authentication](https://playwright.dev/docs/auth).

Для расписания подойдёт локальная automation Codex, если доступный ей browser tool
сможет обращаться к нужному профилю, либо Windows Task Scheduler для отдельного collector.
В текущем чате Chrome доступен через UI, а DOM browser — отдельный браузер без этой
сессии; наличие автоматического доступа к профилю нельзя считать уже настроенным.
Расписание и collector пока предложены, не установлены и не активированы.

Облачный вариант — GitHub Actions schedule с приватным authentication state. Он работает
при выключенном ПК, но переносит сессию аккаунта в CI и требует её обновления при истечении.
Понадобится отдельно согласовать хранение сессии и права на обновление Secrets/manifest;
обычный Pages workflow доступа к Interoves не имеет. У scheduled Actions бывают задержки,
поэтому нельзя обещать обновление ровно в заданную минуту:
[GitHub schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## Что ещё учитывать

- Три Secrets обновляются последовательно, не атомарно. Между upload и commit старый
  manifest не совпадает с новым источником: параллельный deployment завершится ошибкой
  checksum, предыдущий опубликованный сайт останется доступным. Не совмещать публикации;
  после неудачного upload повторить все части и затем согласованный deployment.
- На 129 лесенках источник занимает 81 824 из 135 000 допустимых base64-символов
  текущего скрипта. Рост нелинеен; превышение ёмкости останавливает upload до записи.
  При приближении лимита увеличить число частей согласованно в скрипте, manifest и workflow
  либо отдельно выбрать приватное хранилище. Не ждать отказа ежедневной публикации.
- `archive.previous.json` защищает лишь от последнего локального обновления. Нужна
  отдельная резервная копия полного приватного архива; Secrets обратно не скачиваются.
- Добавочные выгрузки не замечают редакторские исправления старых подсказок. Периодически
  выполнять полный экспорт и проверяемый импорт. Один дополнительный день меняет topology
  и может изменить детерминированную раскладку/путь; стабильность координат между днями
  алгоритмом не гарантирована.
- Поиск раскладки содержит квадратичные участки и bounded DFS для путей; с ростом архива
  следить за временем сборки. Нельзя подменять найденный путь доказанным максимумом.
- Данные и подсказки в готовом графе публичны. Приватность сырого исходника не скрывает
  ответы, необходимые публичному интерфейсу.
