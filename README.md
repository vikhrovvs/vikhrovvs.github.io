# vikhrovvs.github.io

Личная страница с небольшими веб-проектами. Главная страница служит индексом, каждый проект живёт в собственной подпапке и не зависит от сборщика.

## Структура

```text
site/
├── index.html          # главная страница
├── home.css
├── anagrams/           # Словограф и общие данные графа
│   ├── index.html
│   ├── styles.css
│   ├── app.js
│   └── data/graph.json
├── word-route/         # ежедневная игра на том же графе
│   ├── index.html
│   ├── styles.css
│   └── app.js
└── word-grid/          # поиск квадрата 4 × 4 для заданных слов
    ├── index.html
    ├── styles.css
    ├── app.js
    ├── worker.js
    ├── solver.py          # публичный API и координация поиска
    ├── grid_model.py      # геометрия, ввод и первичные проверки
    ├── csp.py             # точный поиск по ограничениям
    ├── complexity.py      # маршруты и оценка запутанности
    ├── subset_selection.py # подбор максимального набора слов
    ├── ALGORITHM.md       # практическая модель и устройство решателя
    └── THEORY.md          # CSP, NP-трудность и границы результата
```

Чтобы добавить проект, создайте новую папку в `site/` и добавьте карточку-ссылку на главную страницу.
В верхней левой части каждой страницы проекта обязательна видимая ссылка «← Проекты»
на главную. Общие стили — `site/project-nav.css`, класс ссылки — `projects-back`.

## Локальный запуск

После свежего клонирования восстановите локальный исходник лесенок в
`data/ladder-graph/archive.json` и выполните `node scripts/build-ladder-graph.mjs`.
Без исходника остальные проекты можно запускать независимо; граф лесенок не загрузится.

```bash
python3 -m http.server 4173 --directory site
```

После запуска доступны:

- главная: http://localhost:4173/
- Словограф: http://localhost:4173/anagrams/
- Словесный маршрут: http://localhost:4173/word-route/
- Словесный квадрат: http://localhost:4173/word-grid/
- Граф лесенок Interoves: http://localhost:4173/ladder-graph/

## Архив лесенок

`site/ladder-graph/` — независимый граф ассоциаций из календарного архива Interoves.
На карте всегда доступны все вершины и рёбра. Поиск и выбор соседа центрируют
камеру на слове; фильтра по лесенке и отдельного режима окрестности нет.
Вершина — точная нормализованная словоформа или словосочетание; ребро неориентированное,
повторные пары объединяются с сохранением всех подсказок и ссылок на исходные задания.
Заметность вершин растёт ступенями по числу связей: 3–4, 5–6, 7–8 и далее.
Слева показано распределение слов по числу соседей и плавно сменяющиеся случайные
примеры; нажатие на пример находит слово на карте. Ниже — распределение пар по
кратности (числу исходных переходов), включая кратность 1. Повторные рёбра
выделены оранжевым, толщиной и меткой ×N; пример в панели находит оба конца ребра. Цвет обозначает компоненту связности. Панель выбранного слова показывает число
лесенок, слов, связей и подсказок в его полной компоненте, её долю в графе и самое связанное слово.
Публичный граф `site/ladder-graph/data/graph.json` генерируется при deployment и исключён
из Git; раздела скачивания на странице нет. Исходный архив хранится локально в
`data/ladder-graph/archive.json` и приватно в трёх GitHub Actions Secrets
`LADDER_SOURCE_1`, `LADDER_SOURCE_2`, `LADDER_SOURCE_3` (gzip + base64).
В репозитории хранится только контрольная сумма и формат `data/ladder-source.json`.
Workflow восстанавливает исходник вне `site/`, проверяет checksum, строит граф,
проверяет сайт и удаляет исходник с runner до загрузки Pages artifact.
Оба JSON отсутствуют в текущем Git, но старые версии остаются в его истории.
Готовый `graph.json` и подсказки остаются публичными на сайте, поскольку нужны интерфейсу.
Локальную копию исходника нужно резервировать отдельно: Secrets не служат скачиваемым архивом.

Для обновления откройте `https://interoves.com/ladder/` в авторизованном Chrome и
выполните проверенный код `scripts/export-ladder.browser.js` в DevTools Console.
Он читает все месяцы календаря, выгружает только слова и подсказки и скачивает JSON;
credentials, результаты игрока и HTML не сохраняются. Сохраните файл как
`data/ladder-graph/archive.json`, затем выполните `node scripts/build-ladder-graph.mjs`.
Сборщик графа откажется работать с неполной выгрузкой. Раскладка детерминирована,
production-зависимости не нужны. Проверка сайта сверяет граф с архивом, если он доступен.

Для обновления приватного источника авторизуйтесь в GitHub CLI (`gh auth login`),
выполните `python3 scripts/ladder-source.py upload`, затем
`node scripts/build-ladder-graph.mjs` и `python3 scripts/check_site.py`.
Команда upload передаёт части через stdin в `gh secret set`, не выводя содержимое,
и обновляет manifest. Закоммитьте manifest вместе с изменениями сайта: push запускает
новую сборку. Несовпадение checksum или отсутствие любой части останавливает публикацию.
При превышении ёмкости трёх Secrets команда останавливается до загрузки;
добавление частей требует согласованного изменения скрипта и workflow.

## Проверка

```bash
python3 scripts/check_site.py
```

Команда проверяет структуру сайта, локальные ссылки, синтаксис Python-решателя и инварианты `graph.json`. Отдельные тесты алгоритма запускаются через `python3 scripts/test_word_grid.py`. Если установлен npm, доступен эквивалентный алиас `npm run check`.

Инструкции для Codex находятся в `AGENTS.md`, а устойчивый контекст проекта — в `MEMORY.md`.

## Публикация

Push в `main` запускает `.github/workflows/pages.yml`. В настройках репозитория GitHub Pages должен использовать источник **GitHub Actions**.

Данные Словографа основаны на частотном списке DetCorpus под CC0. Атрибуция и способ пересборки находятся в `THIRD_PARTY_NOTICES.md` и `scripts/build-data.mjs`.
